# OmniChat Server(サーバー用アプリ)

PC 上で OmniChat サーバーを動かして管理する GUI アプリです(Windows / Linux)。`desktop/` の「OmniChat」(クライアント用ランチャー)とは別のアプリです。

- サーバー本体(Node.js 実行環境、サーバー、Web 画面)を同梱しています。別途 Node.js を入れる必要はありません。
- アプリを起動するとサーバーも起動します。**ウィンドウを閉じてもサーバーは止まりません**(ウィンドウはタスクトレイに隠れ、サーバーはバックグラウンドで動き続けます)。完全に止めるには、トレイのアイコンから「終了(サーバーも停止)」を選びます。トレイを作れない環境では、閉じるとサーバーも止まります。
- 設定画面の「ログイン時に自動で起動」で、PC へのログイン時に自動起動できます。

## 初回
1. アプリを起動します。サーバーが起動し、「最初の管理者アカウントを作成」の画面が出ます。
2. ユーザー名とパスワード(8 文字以上)を入れて作成します。
3. 「状態」画面に表示される URL(他の端末から開く URL)を、スマホやほかの PC のクライアントに入力します。

**管理者の作成は、このアプリ(または `omnichat-admin` / `node dist/admin-cli.js`)からしかできません。** ブラウザやネットワーク越しに、最初の管理者を登録することはできません(先に到達した人が管理者になる事態を防ぐため)。

## 画面
左のナビゲーション(ライト/ダークは OS に追従、日本語/英語)から切り替えます。

| 画面 | できること |
|---|---|
| ダッシュボード | 起動・停止・再起動、稼働時間、ポート、バージョン、他の端末から開く URL(Tailscale / LAN、ワンクリックコピー、スマホ用 QR コード)、更新通知の表示枠 |
| 接続 | 接続中の端末数、ブリッジ(DSH ブリッジを含む)、生成中のチャット数 |
| モデル | 応答しているローカルサーバー(LM Studio / Ollama / llama.cpp / vLLM)とモデル数、設定済みプロバイダー |
| ユーザー | 追加、役割の変更、無効化・有効化、パスワード再設定、新規登録の許可 |
| セキュリティ | 公開範囲(他の端末 / このPCのみ)、ローカル管理トークン、最初の管理者の作成 |
| ログ | ライブ表示(直近 2000 行)、レベル絞り込み、検索、コピー、ファイル保存 |
| 設定 | ポート、公開範囲、公開 URL、データフォルダを開く、Web 検索、自動起動(遅延秒数)、自動バックアップ |
| バックアップ | 作成、削除、復元(復元前に自動で退避バックアップを作り、サーバーを止めて DB を入れ替え、再起動) |
| このアプリについて | バージョン、ライセンス(AGPL-3.0)、ソースへのリンク、言語 |

**管理者のパスワードを忘れたとき**: サーバーを動かしている PC で OmniChat Server アプリを開き、「ユーザー」の管理者の行で「パスワードをリセット」を押します(ログインは要りません)。アプリが無い構成では、`omnichat-admin set-password <名前>` でも再設定できます。そのユーザーは、すべての端末からログアウトされます。

初回起動(セットアップ未完了)では、ウィザード(言語 → 管理者作成 → データ・ポート → ネットワーク → 自動起動)が出ます。自動起動は最初からオンです。

最後の管理者は、降格も無効化もできません。

## 自動起動
設定画面の「PC 起動時に自動で起動」(初回ウィザードでは推奨としてオンになっています)で切り替えます。管理者権限は要りません。表示は OS の実際の状態を反映します。

| OS | 作られるもの |
|---|---|
| Windows | 現在のユーザーのタスクスケジューラ タスク「OmniChat Server Autostart」(ログオン時、遅延つき)。作れない場合は `HKCU\...\Run` の `OmniChatServer`(アプリ内で同じ遅延を待つ) |
| Linux | `~/.config/systemd/user/omnichat-server.service`(`ExecStartPre=sleep N`、`systemctl --user enable`)。systemd --user が使えない場合は `~/.config/autostart/omnichat-server.desktop` |

- **遅延**: 既定 30 秒(0〜300 秒で変更可。`autostart.json` に保存)。Tailscale などのネットワークが起動直後は未準備のためです。
- **ネットワーク待ち**: 自動起動のときは、遅延のあと「既定ルート」または Tailscale のアドレス(100.64.0.0/10)ができるまで最大 120 秒待ち、それでも来なければそのまま起動します。経過は「ログ」に出ます。
- **バックグラウンド起動**: 自動起動は `--minimized --autostart` で始まります。設定の「PC の起動時(自動起動)は画面を出さず、バックグラウンドで起動する」(既定オン)がオンなら、ウィンドウを出さずトレイだけでサーバーが動きます(トレイが作れない場合のみウィンドウを出します)。詳しくは下の「バックグラウンド動作」を参照。
- **解除**: スイッチをオフにすると、上記のタスク / Run 値 / unit / .desktop をすべて削除します。Windows のアンインストーラーも同じ削除を行います。Linux の deb を削除したときは、アプリ内でオフにしてから削除してください(`~/.config` のユーザー設定は deb では消せません)。
- 実機の Windows でのタスク作成は未検証です(XML 生成は単体テスト済み)。

## バックグラウンド動作とトレイ
- **ウィンドウを閉じる = トレイへ隠す**。サーバーは動き続けます。トレイのアイコンを左クリックすると、ウィンドウを表示(最小化も解除)して前面に出します。
- **トレイのメニュー**: 「ウィンドウを開く」/ 状態表示(無効な行: 「Running — http://<IP>:<ポート>」または「Stopped」)/ 「サーバーを再起動」/ 「Web 画面を開く」/ 「終了(サーバーも停止)」。ツールチップは「OmniChat Server — running on port N」。
- **終了**: トレイの「終了」は、サーバーを停止してからアプリを終了します。
- **孤児の防止(Windows)**: サーバー(node)は Job Object(`KILL_ON_JOB_CLOSE`)に入れて起動します。タスクマネージャーなどでアプリが強制終了されたときは、サーバーも OS によって一緒に終了します(ウィンドウを閉じただけでは、アプリが生きているので何も起きません)。念のため、次回起動時に `server.pid` の残骸も片付けます。
- **外部コマンド**: node / schtasks / reg / powershell / taskkill / ipconfig はすべて `CREATE_NO_WINDOW` で起動し、黒い窓は出ません。

### 起動時にウィンドウを出すか
設定の「バックグラウンド」カード(初回ウィザードの自動起動の手順にも同じスイッチ)で、2 つのオプションを `%APPDATA%dev.omnichat.serverackground.json` に保存します。

| オプション | 既定 | 意味 |
|---|---|---|
| `startInBackground` | オン | 自動起動(`--autostart`)で始まったときはウィンドウを出さず、トレイだけで動く |
| `alwaysHidden` | オフ | 手動で起動(スタートメニュー / デスクトップ)したときも、常にウィンドウを出さない |

判定は純粋関数 `should_show_window(first_run, autostart_flag, background_flag, opt_start_in_background, opt_always_hidden, is_second_instance)` で、上から順に最初に当てはまったものが採用されます。

1. 2 回目の起動(単一インスタンスの通知) → 既存のウィンドウを前面に出す
2. 初回(セットアップ未完了) → 必ずウィザードを表示
3. `alwaysHidden` オン → 出さない
4. `--background` を付けて起動 → 出さない
5. 自動起動 かつ `startInBackground` オン → 出さない
6. それ以外(手動起動) → 出す

トレイを作れない環境(Linux でライブラリ欠落など)では、常にウィンドウを出します。

## 保存場所
アプリのデータ領域(OS ごとの標準の場所)に置きます。

| | Windows | Linux |
|---|---|---|
| 設定 `config.env` | `%APPDATA%\dev.omnichat.server\config.env` | `~/.local/share/dev.omnichat.server/config.env` |
| データ(DB など) | `%APPDATA%\dev.omnichat.server\data\` | `~/.local/share/dev.omnichat.server/data/` |

Web 検索の設定と API キーは config.env ではなく、サーバーのデータベースに保存されます(キーは暗号化され、画面には設定済みかどうかだけが出ます。`docs/SEARCH.md` を参照)。

「状態」画面にも実際のパスが出ます。設定ファイルは `KEY=VALUE` の行で、サーバーの環境変数と同じです(`docs/AI-INSTALL.md` の環境変数表)。画面にない設定は、ファイルを直接編集してからサーバーを再起動します。`NODE_OPTIONS` など実行環境を変える変数は、サーバーに渡されません。

## 仕組み(安全性)
- アプリはサーバーを子プロセスとして起動します。アプリが異常終了して残ったサーバーは、次回起動時に `server.pid` を使って片付けます。
- 管理操作は、サーバーの `127.0.0.1` 限定の `/local-admin` API を使います。サーバーが起動のたびに作る一時トークン(`data/local-admin.token`、本人だけが読める権限)が要ります。リバースプロキシや公開ポート経由では使えません。
- 画面(WebView)は、同梱のローカル画面だけを表示し、外部のページは読み込みません。

## サービス版との関係
インストーラー版(Windows サービス / systemd / launchd / Docker)は、これまでどおり使えます。管理者は `omnichat-admin create <名前>`(Docker は `docker exec -it omnichat node dist/admin-cli.js create <名前>`)で作ります。**同じ PC で、サービス版とこのアプリの両方を同じポートで動かさないでください。**

## ビルド
```
cd server-app
npm ci
npm run bundle     # サーバーと実行環境を src-tauri/bundle/server に集める
npm run build      # インストーラーを作る(Windows: NSIS、Linux: AppImage / deb)
```
Linux は `libwebkit2gtk-4.1-dev`、`libayatana-appindicator3-dev` などが必要です(`.github/workflows/server-app.yml` を参照)。`v*` タグを打つと CI が Windows と Linux のインストーラーを作り、リリースの下書きに添付します。

## 更新
- サーバーは新しい版を GitHub で確認します(既定は 12 時間ごと)。新しい版があると、管理者の画面にポップアップが出ます。「今すぐ更新」で、取得・チェックサム検証・更新前バックアップ・入れ替え・再起動まで自動で行われます。
- 再起動はこのアプリが行います(サーバーが終了コード 75 で終わると、アプリがサーバーを起動し直します。2 分間に 5 回までです)。
- 更新前のバックアップは `データ/backups/pre-update-<旧版>-<日時>/` に 3 個まで残ります。健全性確認が失敗すると、自動で旧版と旧データに戻ります。
- 設定の「確認の間隔」「チャンネル」「GitHub トークン(非公開リポジトリ用)」は、サーバーの設定と同じです。詳しくは [UPDATES.md](UPDATES.md) を参照してください。
- インストーラー版(Windows の Inno など)から移行した直後は、一度だけ新しいアプリ(インストーラー)で入れ直す必要があります(UPDATES.md の 11 を参照)。
