# UI の決定事項(ユーザーの指示)

アプリの画面について、ユーザーが決めたことを記録します。UI の作業(M3 以降)は、これに従ってください。

## 画面構成(2026-10-17 のスクリーンショットでの指示)

- **左上**: 「+ New chat」の行をなくし、**Chat / Code の切り替えタブ**にする。履歴とプロジェクトはモードごとに分けて表示する。
- **左下**: 「+ New project」「New chat」「Settings」は、**文字ではなくアイコン**にする(プロジェクト用、チャット用、設定用の 3 つ)。
- **入力欄**: 「Send」ボタンは**アイコン**にする。
- **ヘッダー右上の歯車(チャット設定)は廃止**する。

## 設定の入り口は 1 つ

- 設定が 2 か所あると混同しやすいため、**設定は左下の Settings に一本化**する。
- チャットごとの設定(システムプロンプト、パラメーター、エフォート、ツール、検索モード、応答形式など)も、**Settings の中**で開けるようにする。例: Settings に「このチャット」のセクション(開いているチャットがあるときだけ有効)を置く。
- チャット行の「…」メニュー、ヘッダー、入力欄の周りに、別の設定の入り口を作らない。入力欄の上の Effort / Search のチップは、現在値の表示と素早い切り替えとして残してよい(設定そのものの入り口ではない)。

## 進め方

- UI の本格的な作り込みは、機能追加が終わってから行う。
- アイコンは Google Fonts(Material)を使う。Icooon-mono は、後から追加できる構造にしておく。

## アーティファクト(右パネル)のプレビュー

- 種類は markdown / html / docx / pptx / **xlsx** / **email**。docx・pptx・xlsx はサーバーを呼ばずに端末内で「それらしく」描画する(pptx = 16:9 のスライドカード、docx = 白い用紙とページ区切りの目安、xlsx = 列記号・行番号・シートタブ付きのグリッド。`=SUM` などの簡単な式は計算結果を表示し、それ以外は式の文字列に `fx` の印を付ける)。
- email はヘッダー(To / Cc / 件名)+本文のメールカード。操作は「本文をコピー」「すべてコピー」「メールアプリで開く」(mailto:、長文は切り詰めてトーストで知らせる)、ダウンロードは .eml。`[要確認: ...]` が残っていると警告帯で数を知らせる。
- 「ファイルを開く」(web のみ)で .docx / .xlsx / .pptx / .eml / .md / .csv を取り込める。取り込んだ内容はパネルに表示され、「チャットで使う」で ```artifact ブロックとして送れる(「3 枚目を短く」などの修正依頼用)。
- スラッシュメニューに、メール用の組み込みプロンプト 5 種(返信を作成 / 丁寧に言い換え / 短く要約して返信 / 断りの返信 / 日程調整の返信)がある。

## スラッシュコマンドと使用量画面
- チャット欄で `/` を入力するとコマンド(compact, context, usage, clear, help, rename, model, effort, export, pin, unpin, retry)が既存の `/new` 等より先にメニューへ出る。引数付きは `/name ` を挿入し、Enter で実行。結果は会話欄末尾のローカルカード(保存・送信されない、最大4枚、チャット切替で消える)。コードタブでは compact/context/effort を隠す。
- 使用量: 設定 > 接続 > 使用量(`UsageScreen`)。期間 7/30/90日/全期間、日別の積み上げバー(入力/出力/思考、タップで数値)、合計・回答数・チャット数・平均、上位チャット(タップで開く)、モデル別。View だけで描画しチャートライブラリは未使用。一時チャットは集計しない。詳細は PROTOCOL-v7-usage.md。
