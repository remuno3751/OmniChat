# デスクトップ・ペットと、Android の長押し移動(v0.5.6)

状態: 設計(2026-10-24)。実装は `feat/v056`。

## 目的
1. **デスクトップ版のアプリ(Tauri)では、ペットを OmniChat のウィンドウの外、OS のデスクトップ上にも出せる。** 常に最前面・背景透明・枠なしの小さなウィンドウに、ペットと吹き出し(考え中・回答の生成中・作業中など)を出し、キャラクターはアニメーションで動く。ドラッグで好きな場所へ動かせる。
2. **Android(タッチ端末)では、ペットを長押しして動かせる。**

## 前提(既存の作り)
- デスクトップ版は、サーバーの Web UI を開くだけの薄いランチャー。リモートのページには、Tauri の IPC を一切渡さない。シェルとの会話は、`https://omnichat-desktop.invalid/<path>?id=<n>&...` への**ナビゲーションの信号**で行う(`desktop/src-tauri/src/lib.rs` の `handle_desktop_url`、ページ側は `UPDATE_BRIDGE_JS` が足す `window.__OMNICHAT_DESKTOP__` のメソッド)。ペットのウィンドウも、同じ方式にする。
- ペットの画像(スプライトシート・静止画)は、サーバーに保存され、同じアカウントのどの端末でも取得できる(`apiV4.pets()`、`apiV4.petSheetBlobUrl(id)`)。ペットの選択と表示は、端末ごとの設定(`useDevice().pets`)。
- アプリ内の表示は `app/src/components/PetOverlay.tsx`、状態は `app/src/petState.ts`(`usePetMode`、行と動きの対応)。

## シェル側(Rust、`desktop/src-tauri`)
新しい信号(すべて `https://omnichat-desktop.invalid/` の下。メイン画面とペット画面の両方で受ける):
| 信号 | 呼び出し元 | 動作 |
|---|---|---|
| `/pet/show?id=<n>[&x=<int>&y=<int>]` | メイン画面 | ペットのウィンドウ(ラベル `pet`)を作る。すでにあれば表示して前面へ。URL は、**保存済みのサーバー URL の origin + `/?desktopPet=1`** から、シェルが作る(ページから URL を渡させない)。x, y は物理座標(省略時は、保存済みの位置、なければ主モニターの作業領域の右下)。位置は、必ずいずれかのモニターの内側に収める。 |
| `/pet/hide?id=<n>` | メイン画面 | ウィンドウを閉じる(破棄)。 |
| `/pet/status?id=<n>` | メイン画面 | `{visible:boolean}` を返す。 |
| `/pet/drag?id=<n>` | ペット画面だけ | ペットのウィンドウの `start_dragging()` を呼ぶ(マウスのボタンを押した瞬間に呼ばれる)。 |
ページへの返事は、既存の `reply_update(app, id, value)`(`__resolve`)を使う。
- ウィンドウの仕様: ラベル `pet`、幅 320・高さ 360(論理 px)、`decorations(false)`、`transparent(true)`、`always_on_top(true)`、`skip_taskbar(true)`、`resizable(false)`、`shadow(false)`、`focused(false)`(フォーカスを奪わない)、`visible_on_all_workspaces(true)`(Mac)。ナビゲーションは、サーバーの origin と、信号のホストだけ許可する(メイン画面の許可の方式に合わせる)。外部へのリンクは開かない。
- 位置の保存: ペットのウィンドウの `Moved` を、0.5 秒まとめて、アプリのデータフォルダの `pet-window.json`(`{x,y}`)に書く。次に作るとき、読んで、モニターの内側に収める。
- メイン画面が閉じる・アプリが終了するときは、ペットのウィンドウも閉じる。
- ペット画面にも、`window.__OMNICHAT_DESKTOP__`(`petDrag`, `petHide` だけ)の橋渡しを、初期化スクリプトで足す。メイン画面の橋渡しには `petShow`, `petHide`, `petStatus` を足す(`UPDATE_BRIDGE_JS` を拡張)。
- macOS: 透明なウィンドウには、`tauri.conf.json` の `app.macOSPrivateApi: true` と、`Cargo.toml` の tauri の `macos-private-api` の feature が要る。
- ペットのウィンドウは、IPC の権限を持たない(`capabilities` に足さない)。

## ページ側(アプリ、`app/`)
- **デスクトップ・ペットのページ**: URL に `desktopPet=1` があるとき、アプリ全体の代わりに `DesktopPetPage` だけを描く(ログイン済みの保存領域を、そのまま使う)。`html`/`body`/ルートの背景は透明。構成: 下に、ペットのスプライト(サイズは `pets.size`、`activity` を反映)。上に、吹き出し。ペットの上で、マウスのボタンを押したら `__OMNICHAT_DESKTOP__.petDrag()` を呼んで、ウィンドウを動かす。ダブルクリックで、手を振る動き。右クリックで、小さなメニュー(「ペットを隠す」= `petHide()` と、設定の `desktopPet.enabled` を false に)。
- **状態の受け渡し**: メイン画面が、`BroadcastChannel('omnichat-pet')` に `{ type:'state', mode, label, detail, at }` を送る。`mode` は `petState.ts` のモード(idle / thinking / working / writing / done / error / waiting …、実際の名前に合わせる)。`label` は、吹き出しの文(下の表)。ペットのページは、受け取って、アニメーションと吹き出しを更新する。メイン画面が、10 秒以上何も送らなければ、待機に戻す。ペットのページが起動したときに、状態を問い合わせる(`{type:'hello'}` → メインが現在の状態を返す)。
- **吹き出し**(`app/src/petBubble.ts` の純粋関数 `bubbleFor(mode, detail, lang)`): 待機は出さない。考え中「考え中…」/ 回答の生成中「回答を作成中…」/ ツール実行中「{ツール名} を実行中…」(ツール名は短く丸める)/ 承認待ち「承認を待っています」/ 完了「できました!」(4 秒で消える)/ エラー「エラーが起きました」(6 秒で消える)。英語は、"Thinking…" / "Writing the answer…" / "Running {tool}…" / "Waiting for approval" / "Done!" / "Something went wrong"。ふわっと出る(opacity)短いアニメーション。文字は 2 行まで、はみ出したら省略。
- **設定**(外観 → ペット): 「デスクトップにペットを表示(デスクトップ版のみ)」のスイッチ(`useDevice().pets.desktop`、既定 false)。`window.__OMNICHAT_DESKTOP__?.petShow` があるときだけ表示。オンにすると `petShow`、オフで `petHide`。アプリ起動時に、オンなら `petShow`。オンのとき、アプリ内のペット(`PetOverlay`)は、既定で隠す。ただし「アプリ内にも表示」のチェックで、両方出せる。
- **共通化**: `PetOverlay.tsx` から、スプライトの描画とアニメーション(`PetSprite`)を、再利用できる形で取り出す(アプリ内の見た目と動きは変えない)。

## Android(タッチ端末)の長押し移動
- ネイティブ(`Platform.OS !== 'web'`)では、ペットのスプライトが常にタッチを受ける(`pointerEvents: 'auto'`)。**長押し(450 ms)で、移動モード**に入る: 短く振動(`Vibration.vibrate(15)`)、ペットの縁に輪郭(アクセント色)と少し拡大(1.08 倍)。そのまま指を動かすと、ペットが動く。指を離すと、位置を保存して終了。移動モードに入る前に、指が 8 px 以上動いたら(スクロールの意図)、長押しをキャンセルする。短いタップは、手を振る動きだけ(下のボタンには通らない。ペットは小さいので許容)。
- Web のつまみ(⋮⋮)は、Web のまま。ネイティブでは、つまみを出さない。
- 設定のヒント(ネイティブ): 「ペットを長押ししてから動かすと、好きな場所に移せます。」(`pets.drag.hint` を、ネイティブ用に分ける)。

## 検証(実機が使えない部分)
- Rust: `cargo check`(Windows)と、URL の解析・位置の補正の単体テスト。
- アプリ: 純粋関数(`bubbleFor`、位置、長押しの判定)の単体テスト。
- ブラウザ: `/?desktopPet=1` を、通常のブラウザで開いて、BroadcastChannel の別タブから状態を送り、吹き出しとアニメーションを確認する。
- 実機(デスクトップのウィンドウの透明・最前面・ドラッグ、Mac の透明、Android の長押し)は、ユーザーの確認が要る。

# 追加仕様 v2: 見逃さない通知・複数チャット(2026-10-24)

## 目的
- アプリを開かずに、ペットだけをデスクトップに出しているときでも、**作業が終わったことに気づける**。完了は、緑のチェックマークと「回答を確認してください」を出し、**アプリを開いて確認するまで消えない**(吹き出しの ✕ でも消せる)。
- **複数のチャットが同時に動いていても、すべて見える**。設定で、「<> で切り替える(ページ式)」か「吹き出しを並べる(積み重ね式)」かを選べる。

## 状態の受け渡し(BroadcastChannel `omnichat-pet`、v2)
メイン画面 → ペット:
```
{ type:'state', v:2, at, appFocused:boolean,
  items:[ { id:<会話の id>, title:<短い題名>, mode:<PetMode>, label:<吹き出しの文>, detail:<ツール名など>, at, unread:boolean } ] }
```
- `items` には、(1) いま動いている会話(`mode` が idle 以外)、(2) 完了・エラーで終わって、まだ見られていない会話(`unread:true`)を入れる。見られた会話、何も起きていない会話は入れない。最大 8 件。
- `unread` は、実行が終わった時点で、アプリのウィンドウにフォーカスがない(`document.hasFocus()` が false か `visibilityState !== 'visible'`)、または、その会話がいま画面に出ていないときに true。**アプリにフォーカスがあり、その会話が画面に出た時点**(または、ペットから dismiss が来た時点)で、メイン画面が `unread` を外す。
- アプリにフォーカスがあるときの完了は、従来どおり 4 秒で消える(`unread` にしない)。
ペット → メイン画面: `{type:'hello'}`(現在の状態を返す)、`{type:'dismiss', id}`(その会話の unread を外す)、`{type:'open', id}`(アプリを前面に出して、その会話を開く。unread も外す)。

## ペットの画面
- 吹き出しの内容: 動いている = 状態の文(従来どおり)+ 会話の題名(小さく、1 行、省略)。**完了で unread = 緑の丸にチェックマーク(✓)+「完了しました。回答を確認してください」**。**エラーで unread = 赤の丸に「!」+「エラーが起きました。確認してください」**。unread の吹き出しには ✕ ボタンがあり、押すと dismiss。吹き出しの本文を押すと open(アプリを開いて、その会話へ)。
- 複数の表示は、設定 `pets.multi`(`'pager'` 既定 / `'stack'`)で切り替える。
  - **pager**: 吹き出しは 1 つ。左右の `‹` `›` と「2/3」の表示で切り替える。初期の選択は、unread で一番新しいもの、なければ、動いているもので一番新しいもの。新しい項目が増えても、いま見ている項目は変えない(「2/3」の分母だけ変わる)。選択中の項目が消えたら、隣へ。
  - **stack**: 吹き出しを縦に積む(ペットの真上から上へ)。入りきらない分は「+N 件」の小さい吹き出し。1 つの高さを約 52px として、`(360 − ペットの高さ − 16) / 52` 個まで。
- スプライトの動き: 動いている項目があれば、表示中の(pager なら選択中の)項目の状態に合わせる。なければ、unread があれば、ときどき手を振る(待機に、まれに wave を混ぜる)。何もなければ待機。
- 設定画面(外観 → ペット)に、「複数のチャットの表示」: 「切り替える(‹ ›)」/「並べて表示」。デスクトップ版でペットを出すときだけ表示。

## シェル(Rust)の追加
- `/pet/focus?id=<n>`(ペットのウィンドウからだけ): メイン画面を、表示・最小化解除・フォーカス・最前面へ。返事 `{ok}`。ペット画面の橋渡しに `petFocusApp()` を足す。

## そのほか(同じ作業で直す)
- ペットの右クリックの「ペットを隠す」で、メイン画面の `pets.desktop` がすぐ反映される(`storage` イベントで、デバイス設定を読み直す)。
- 端末の設定にペットの id がなく、同期済みの `activePetId` があるときは、それを使う(「ペットを表示」の既定は、同期済みの選択があれば、オン)。
- とても狭い幅で、ペットが下のボタンに重ならない(アプリ内の表示。モバイル幅では、入力欄の上に避ける)。
