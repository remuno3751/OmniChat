# 設計メモ: 共有プロバイダーと、ユーザーごとのモデル制限(提案・未実装)

状態: **承認済み・実装中**(2026-10-19)。決定事項は末尾。

## なぜ必要か

今のプロバイダー(接続先)は**ユーザーごとの持ち物**です(`providers.user_id`)。各ユーザーが、自分の接続先と API キーを登録します。この作りのまま「管理者が、ユーザーごとに使えるモデルを制限する」を足しても、ユーザーが自分で好きな接続先を足せるので、制限になりません。

家族や友人と 1 台のサーバーを共有するときの実際の使い方は、次のとおりです。

- 管理者が、自宅の LLM サーバー(LM Studio / Strata など)や、有料 API のキーを、サーバーに 1 回だけ登録する。
- 家族や友人は、**キーを知らないまま**、管理者が許可したモデルだけを使う。

## 提案

### 1. 共有プロバイダー
- 管理者が作るプロバイダーに「共有」の印を付けられる(`providers.shared INTEGER NOT NULL DEFAULT 0`)。所有者は管理者のまま。
- 一般ユーザーの接続先一覧に、許可された共有プロバイダーが**読み取り専用**で現れる。URL と API キーは**返さない**(名前、種類、モデル一覧だけ)。
- 共有プロバイダーを使うチャットは、サーバーが管理者の行(キー)で上流を呼ぶ。メッセージの保存先は、利用者本人の会話。

### 2. ユーザーごとのモデル制限
- 表 `user_model_grants (user_id, provider_id, mode, models)`。`mode` は `all`(そのプロバイダーの全モデル)/ `list`(`models` に書いたモデル ID だけ)/ 未登録 = 使えない。
- 管理者は、全モデルを使える(制限の対象外)。
- 判定は 2 か所で行う: (a) モデル一覧の応答から、許可されないモデルを除く、(b) チャット送信・再生成・比較・ベンチ・`/v1` で、許可されないモデルが指定されたら 403(`code: "model_not_allowed"`)。**一覧から隠すだけでは不十分**で、(b) が本体。
- 既定: 新しいユーザーは、共有プロバイダーを**何も使えない**(管理者が許可して初めて使える)。変更したい場合は、管理者設定の「新規ユーザーの既定」で選ぶ。

### 3. 自分の接続先を足すことの可否
- 管理者設定 `allowOwnProviders`(既定 true=今の動作を変えない)。false にすると、一般ユーザーは自分の接続先を追加できない(家族向け運用)。
- 自分の接続先には、モデル制限はかからない(自分のキーなので)。

### 4. 管理 UI
- クライアントの管理画面: 共有にするスイッチ(プロバイダーごと)、ユーザー別の許可の編集(ユーザー × プロバイダー、全モデル / 選択)。
- OmniChat Server アプリの「ユーザー」画面: 同じ設定(ローカル管理 API 経由)。

## セキュリティ
- 共有プロバイダーの URL とキーは、一般ユーザーに**絶対に返さない**(API、同期、設定の書き出し、ログ)。
- 共有プロバイダー経由のツール実行・引用取得で、管理者のキーが外へ出ない。
- 使用量の記録(メトリクス)は、利用したユーザーごとに残す。上限(トークン数 / 日)は**この設計の対象外**(次の段階)。
- 無効化したユーザーの許可は、そのまま残してよい(再有効化で復活)。削除時は消す。
- メンテナンスモード(実装済み)と同じ判定の場所に置く。

## 工数の目安
サーバー 2〜3 日(DB・判定・同期・テスト)+ クライアント 1 日 + サーバーアプリ画面 0.5 日。最初の見積もり(1.5〜2 日)より増える。

## 決定事項(2026-10-19、ユーザー承認)
1. 共有プロバイダーという考え方で進める。
2. **新規ユーザーの既定は変更できる**: 管理者設定 `defaultSharedAccess` = `none`(既定。何も使えない)/ `all`(全共有プロバイダーの全モデル)。個別の許可(行)がないユーザーにだけ適用する(判定時に評価するので、既定を変えると、個別設定のないユーザー全員に反映される)。個別の行は、既定より常に優先する(`mode: none` で「使えない」と明示もできる)。
3. 一般ユーザーが自分の接続先を足すことは、既定で**許可**する(`allowOwnProviders` = true)。
4. 使用量の上限は、次の段階に回す。

## 契約(実装の共通理解)
- `providers.shared INTEGER NOT NULL DEFAULT 0`。共有にできるのは管理者所有のプロバイダーだけ。
- 表 `user_model_grants (user_id TEXT, provider_id TEXT, mode TEXT CHECK(mode IN ('all','list','none')), models TEXT /* JSON 配列 */, updated_at INTEGER, PRIMARY KEY (user_id, provider_id))`。
- 判定: `modelAllowed(user, providerId, model)` = 管理者 → true。自分のプロバイダー → true。共有プロバイダー → 個別の行(all / list に含む / none)があればそれ、なければ `defaultSharedAccess`(all → true、none → false)。共有でも他人のでもないプロバイダー → false。
- 一般ユーザーへ返す共有プロバイダーは、`{ id, name, kind, shared: true, readOnly: true }` と許可されたモデルだけ。`baseUrl`、`apiKey`、`model`(既定モデルの名前は可)は返さない。
- 拒否は、WebSocket のエラー(`code: "model_not_allowed"`)と、HTTP 403(`{ error: { type: "forbidden", code: "model_not_allowed", message } }`)。メンテナンスモードの遮断と同じ入口に置く。
