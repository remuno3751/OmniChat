## 1. 画面の見取り図

- **サイドバー**: `+ New chat`(新しい会話)、`+ New project`(新しいプロジェクト)、会話とプロジェクトの一覧、下部の **Search history**(Ctrl/Cmd+K)、**Settings**
- **プロジェクトの行**: `+`(そのプロジェクトに新しい会話)、`⋯`(プロジェクトの設定)
- **会話の画面の上部**: 戻る、会話名、接続状態(LatencyBadge)、モデルの選択、**Chat settings** ボタン
- **入力欄の上**: 文脈の使用量(ContextBar)
- **入力欄の下**: 推論エフォートのチップ(Default / low / medium / high / max)、Web 検索のチップ(Inherit / Off / Auto / Always)、開発者モードでは応答形式のチップ

## 2. アカウントと端末

- **管理者はサーバー上で作ります**(`omnichat-admin create <名前>`。HTTP からは作れません)。一般ユーザーは、サーバーで `ALLOW_REGISTRATION=1` にすると管理者の作成後に自分で登録できます(既定は拒否)。ユーザー名は 3〜32 文字、パスワードは 8 文字以上。
- ログインすると、その端末が **Devices** に登録されます。Settings → Account → **Devices** で一覧を見て、**Revoke** を押すとその端末はすぐにサインアウトされます。
- **Log out** は今の端末だけを失効させます。

## 3. 接続先(プロバイダー)

Settings → **Providers** → **+ Add provider**。

1. **Presets**(OpenAI / DeepSeek / Ollama / LM Studio / DeepSeek Harness (PC bridge))から選ぶと、種類と URL が入ります
2. **Kind**: `openai-compatible`(OpenAI 互換の API)か `dsh-bridge`(PC の dsh)
3. **Base URL** と **Model**(既定のモデル ID)
4. **API key**: 入力すると、サーバーの DB に保存されます。クライアントには返りません(一覧には `key set` と表示)

- **Auto-detected on the server**: サーバー PC で LM Studio(1234)、Ollama(11434)、llama.cpp(8080)、vLLM(8000)が動いていれば、ここに出ます。**Add** で追加できます。
- 一覧の **Edit** と **Delete** で変更・削除します。削除は論理削除です。

注意: API キーは**サーバーの DB に平文で**保存されます。バックアップにも入ります([BACKUP.md](BACKUP.md))。

## 4. モデルの選択

会話の上部のモデルボタンで、プロバイダーごとのモデル一覧を開きます。

- 選んだモデルは**その会話に保存**されます。新しい会話は、直前に選んだモデルから始まります。
- **プロジェクトに既定のモデル**がある場合、そのプロジェクトの新しい会話はそれを使います。
- 一覧にないモデルは **Custom model id…** で直接入力できます。
- OpenAI 互換のモデル一覧は `{baseUrl}/models` から取ります。embedding、rerank、whisper、tts、moderation を含む ID は一覧から除かれます。
- **LM Studio / Ollama** では、読み込み状態、VRAM、量子化が表示され、各モデルの行から読み込み(Load)と解放(Unload)ができます。
- dsh のモデルは、ブリッジが報告したものです([DSH.md](DSH.md))。

## 5. チャットの送信・停止・分岐

- **送信**: 入力欄で書いて送信します。応答はストリーミングで少しずつ表示されます。
- **停止**: 生成中は送信ボタンが **Stop** に変わります。止めた応答は `stopped` として残ります。
- **再生成**: アシスタントの応答のメッセージ操作から **Regenerate** を選ぶと、同じ質問への別の答えを作ります。古い答えは残り、枝が増えます。
- **編集して再送**: 自分の発言のメッセージ操作から **Edit & resend** を選んで編集して送ると、その発言の**兄弟**として新しい枝ができます。
- **枝の切り替え**: 枝があるメッセージには `‹ 2/3 ›` のような表示が出て、矢印で別の枝に移れます。

同じ会話を複数の端末で開いても、同期されます。生成中に画面を閉じても、サーバーは生成を続けます。戻ったときに途中経過が表示されます。

## 6. プロジェクト

- サイドバーの **+ New project** で作ります。名前、システムプロンプト、既定のモデル、推論エフォート、ツールと Web 検索の設定を持てます。
- 既定のモデルを **Not set** にすると、新しい会話は直前に選んだモデルを使います。
- プロジェクトの **Delete project** で削除すると、中の会話は**未分類**に移ります(会話は消えません)。
- プロジェクトで設定した値は、その中の会話の既定になります。会話で別の値を選べば、会話の値が優先されます。

## 7. システムプロンプト

システムプロンプトは **全体 → プロジェクト → チャット** の 3 層で組み立てられます。

| 層 | どこで設定するか |
|---|---|
| 全体 | Settings → **Defaults for all chats** → **Global system prompt** |
| プロジェクト | プロジェクトの設定 → **System prompt** |
| チャット | チャットの設定(Chat settings)→ **System prompt for this chat** |

各層のモードは次のどちらかです。

- **Append**(既定): 上の層の内容に続けて追加する
- **Replace**: 上の層の内容をすべて捨てて、この層の内容だけを使う

**プリセット**: 欄の **Presets (n)** から保存済みの文章を **Use**(置き換え)か **Append**(末尾に追加)できます。**Save as preset** で今の文章を保存します。

## 8. 推論エフォート

推論モデルの考える量を指定します。値は `low` / `medium` / `high` / `max` と **Default**(継承)です。

- **次の 1 通だけ**: 入力欄のチップで選ぶと、次の送信だけに使われます。
- **この会話に固定**: チャットの設定、またはチップの固定の操作で、会話に保存されます。
- **プロジェクト**と**全体**の設定が既定になります。解決の順は「次の 1 通 → 会話 → プロジェクト → 全体」です。

推論に対応していないモデルでは、エフォートのチップが選べなくなります。モデルごとの対応は `effort-map.json` で設定できます(場所は `EFFORT_MAP`。無ければ既定値で作られ、編集すると再読込されます)。

## 9. 思考過程(thinking)

推論モデルの思考は、回答とは別に保存されます。

- 既定では**折りたたまれています**。「Thinking… N tokens」のように、トークン数と所要時間が表示されます。
- 開くと内容が読めます。回答の本文には混ざりません。
- 思考の内容は、次の送信で文脈として再び送られることはありません(既定)。

## 10. 文脈の使用量(コンテキストバー)

入力欄の上に「使用トークン / 上限」が表示されます。

- **内訳**: システムプロンプト、履歴、添付、ツール、入力中の文章
- **80% 以上**で警告が出ます
- **Context window** の画面で、返答のために空けておく量(**Reserved for the reply**)と、モデルごとの上限の上書き(**Context limit (tokens)**)を設定できます

### 上限を超えたとき

Settings → Defaults for all chats → **When the context is full** で選びます。

| 選択 | 動き |
|---|---|
| **Drop oldest**(既定) | 古いメッセージを送る文脈から外す。会話自体は変わらない |
| **Summarize** | 古い部分を、同じモデルに作らせた短い要約に置き換える(追加で 1 回の要求) |
| **Stop** | 送らずに止める。「Context is full」と表示され、**Switch to Drop oldest** で切り替えられる |

トークン数は、バックエンドが分かれば実測値(backend)、分からなければ推定値です。推定のときは表示に `est.` が付きます。

## 11. 速度・統計

- **メッセージごとの表示**(MetricsLine): 最初のトークンまでの時間(TTFT)、prefill と decode の速さ(tok/s)、トークン数。推定値には `est.` が付きます。
- **統計**: Settings → Account → **Statistics**。全体、直近、モデル別の平均と、decode 速度の折れ線グラフ。**CSV** で書き出せます(`GET /stats/export`)。

速度の値は、バックエンドの報告値を優先し、報告がなければサーバーが推定します。推定と実測の違いは [DEVELOPER.md](DEVELOPER.md) の「計測の注意」にも書いています。

## 12. 接続状態(レイテンシ)

ヘッダーの接続表示は、ping の平均値と経路を示します。

- **経路**: `loopback`(同じ PC)、`LAN`、`VPN`(Tailscale など)、`external`(外部)
- **色**: 150ms 未満は良好、150〜500ms は遅い、500ms 超は悪い、切断
- 切断しても自動で再接続します(1 秒、2 秒、5 秒、10 秒、30 秒と間隔を延ばす)。入力中の下書きと送信中の状態は保たれます。
- WebSocket だけが切れて HTTP では届く場合は、その旨が表示されます。

## 13. ツールと Web 検索

### 画面

Settings → **Tools, plugins & search**。

- **ツールの一覧**: 組み込みの `web_search` と、サーバーのプラグイン(読み込みエラーも表示)
- **全体の設定**: 使うツールと、既定の検索モード
- **承認の一覧**: 「常に許可」にしたツールと、取り消し(Revoke)
- **Reload plugins**(管理者): プラグインを読み直す
- **検索の状態**: 接続できるか。**Test search**(管理者)で検索結果を確かめる

ツールは会話・プロジェクト・全体の順に解決され、会話かプロジェクトに設定があれば全体は使われません。

### 検索モード

入力欄の **Web search** チップ(画面表示は Inherit / Off / Auto / Always)。

| モード | 動き |
|---|---|
| **Off** | 検索しない |
| **Auto** | モデルが必要と判断したときに検索する(ツール呼び出しに対応したモデル) |
| **Always** | 送信のたびに、最新の発言で 1 回検索する |

既定は **Off**。Inherit はプロジェクトまたは全体の設定に従います。

### 承認

ネットワークを使うツール(`web_search` を含む)は、初回に承認が必要です。承認ダイアログには、ツール名、引数、宣言された権限が出ます。

- **Allow once**: この 1 回だけ
- **Always allow**: 以後、そのツールは承認なしで使う
- **Deny**: 使わせない

承認が 120 秒なければ拒否扱いになります。

### 結果の表示

- ツールの呼び出しは、メッセージの下にカードで表示されます(名前、引数、状態、所要時間、結果)。
- 検索の出典は **Sources** として表示され、本文の `[n]` は出典を指します。

検索の設定の詳細は [SEARCH.md](SEARCH.md)、プラグインの作り方は [PLUGINS.md](PLUGINS.md) を参照してください。

## 14. 履歴検索

- サイドバーの **Search history**、または **Ctrl/Cmd+K**。
- 全会話の本文と会話名を検索します。日本語の部分一致が効きます。
- 結果は新しい順です。一致した箇所は強調されます。タップ(クリック)すると、その会話の該当メッセージに移ります。
- 3 文字未満の語は、部分一致の単純な検索になります。
- 検索できない場合は、サーバーが古い版である可能性があります(「History search is not available on this server」と表示)。

## 15. エクスポート・インポート・バックアップ

| やりたいこと | 操作 |
|---|---|
| 1 会話を Markdown か JSON で保存 | 会話の操作メニュー → **Export as Markdown** / **Export as JSON**(枝の選択と思考過程の有無を選べる) |
| 全部のデータを JSON で保存・取り込み | Settings → **History and data** → **Data: export / import**(取り込みは Web とデスクトップ版) |
| 設定ファイルの入出力 | Settings → **Data**(データ画面)の設定ファイル |
| サーバーのバックアップ(管理者) | Settings → **History and data** → **Backup (admin)** |

詳細と注意([BACKUP.md](BACKUP.md))。インポートは既存のデータを上書きせず、常に新しい ID で作ります。

## 16. API キーと OpenAI 互換エンドポイント

Settings → **Developer mode** をオンにすると、Settings → Developer → **API keys & OpenAI-compatible endpoint** が出ます。

- 名前を入れて **Create key** で作成します。キーは**作成直後の一度だけ**表示されるので、**Copy key** ですぐに保存してください。
- 一覧には、名前、接頭辞、作成日、最後に使った日時が出ます。**Delete** で失効させます。
- エンドポイントは `http://<サーバー>:8787/v1`(`base_url` に指定)。モデル名は `<プロバイダー名>/<モデル ID>` です。

API の詳細は [API.md](API.md) を参照してください。

## 17. 開発者モード

Settings → **Developer mode**(すべての端末で同じになります)。オンにすると次が出ます。

- メッセージの **Developer: message debug**: **Final prompt**(実際に送られたプロンプト)、**Raw JSON**(生の応答)、**Speed**、**Logprobs**
- 入力欄の応答形式のチップ(次の 1 通だけ JSON を指定)
- 全体・プロジェクト・チャットの **Sampling parameters**(温度など)とモデルごとの生成パラメーター
- Settings → Developer の **Compare models**(モデル比較)と **Benchmarks**(ベンチマーク)

詳細は [DEVELOPER.md](DEVELOPER.md) を参照してください。

## 18. dsh の遠隔操作

Settings → Providers → **+ Add provider** → プリセット **DeepSeek Harness (PC bridge)**。Base URL にブリッジの名前を入れます。ブリッジの起動と設定は [DSH.md](DSH.md) を参照してください。

dsh の会話には、分岐、OmniChat のツールと Web 検索、自動タイトルは使えません([DSH.md](DSH.md) の「dsh プロバイダーの制限」)。

## 20. ロック(Code / アプリ全体)

Code の画面(セッション一覧と Code モードの会話)、または アプリ全体を開く前に認証します。設定は端末ごとで、サーバーには送りません。

- **認証の方法**: 端末に指紋・顔認証、または画面ロック(PIN/パターン)が登録されていれば OS の認証画面を使います。使えない端末(Web、デスクトップの画面を含む)はアプリの PIN(4〜8 桁)です。
- **ロックの範囲**(設定 → Code → ロック): **ロックしない** / **Code のみ**(既定。以前の「Code のロック」を使っていた端末は、そのまま) / **アプリ全体**(起動時と、離れて戻ったときに、チャット・設定・モデル選択を含む全画面を認証で覆う。開いているダイアログの上にも出る)。ログイン画面はロックしません(守るものがないため)。範囲を弱めるとき(アプリ全体→Code のみ→なし)は、先に認証が要ります。
- **離れたときのロック**(Android / iOS): アプリがバックグラウンドに行く(ホーム、アプリ切替、画面オフ)と、「離れてからロックするまで」(すぐ(既定) / 1 分 / 5 分 / 15 分)に従ってロックします。戻ると認証を求めます。OS の認証画面が出ている間(と直後 1.5 秒)の「非アクティブ」は、ロックの対象にしません(認証のループを防ぐ)。Web / デスクトップは、タブやウィンドウを隠してもロックしません(読み込み時のロックのみ)。
- **再ロック**(Code のみ): 毎回 / 1 分 / 5 分(既定) / 15 分 / アプリを閉じるまで。アプリ内で Code を開いたままの経過時間に使います。離れたときのロックは、これより優先します。
- **PIN の保存**: ソルト付きの SHA-256 を 10,000 回繰り返した値だけを保存します(平文は残りません)。5 回連続で間違えると 30 秒待ち、以後は失敗のたびに倍(上限 15 分)です。
- **PIN を忘れたとき**: 認証画面の「ログアウトして PIN をリセット」。ログアウトで PIN とそのロックアウトは消えますが、**ロックの範囲は変わりません**(ロックが勝手に外れることはありません)。ログインし直すと、範囲が「アプリ全体」/「Code」なら新しい PIN の設定画面が出ます。OS 認証の端末は PIN を使わず、ログアウトだけで済みます。
- **無効化・PIN の変更**: どちらも先に一度認証が要ります。
